# 고CPM 파이프라인 구현

## 왜 이 계층이 필요한가

정치·시사 라이브는 CPM 200~600이다. 3시간이면 5만 건이 넘는다. 라이브 쇼핑(CPM 20~40, 1시간)에서 잘 돌던 코드가 여기서 깨지는 이유는 **모든 댓글을 AI에 넘기는 구조**이기 때문이다. 입력 토큰이 CPM에 비례해 선형 증가하면 비용·지연·토큰 한도 어디에서든 먼저 막힌다.

해법은 계층 분리다. **L1이 전량을 비용 0으로 처리하고, AI에는 집계 통계 + 대표 표본만 넘긴다.** 그러면 호출당 입력이 CPM과 무관하게 상수로 고정된다.

```
[전체 댓글 100%]
   ├─ L1 로컬 (비용 0, 전량)   ← 이 스킬의 범위
   │    사전 매칭 · dedupe · 도배 탐지 · CPM/스파이크 · 리스크 1차
   │    → 집계 통계 + 리스크 후보 + 대표 댓글 풀
   ├─ L2 AI 정밀 태깅 (표본 + 타깃 전수)
   └─ L3 처방 생성
```

## 금지 패턴

다음은 저volume에서만 성립한다. 신규 코드에 복제하지 마라. 왜 깨지는지 알면 변형도 피할 수 있다.

| 패턴 | 저CPM | 고CPM에서 무슨 일이 나는가 |
|------|-------|---------------------------|
| `slice(-80)` 고정 말단 윈도우 | 40초에 13건 → 다 들어감 | 40초에 200건 → **60% 유실** |
| `slice(0, 150)` 앞에서 자르기 | 총 1,200건 중 12% 표본 | 5만 건 중 **도입부 0.3%** — 리포트가 방송을 대표하지 못함 |
| 메시지 ID 전량 해시 캐시 키 | 유입이 느려 ID 집합이 자주 동일 → 히트 | 매 호출 집합이 바뀜 → **히트율 0** |
| `messages` 무제한 누적 | 2,400개 → 문제없음 | 5만 개 React 상태 → **렌더 정지** |

대체안: 말단 윈도우 → 층화 표본, 앞자르기 → 전 구간 버킷 표본, ID 해시 → `(방송ID, 시간 버킷, L1 통계 시그니처)`, 무제한 누적 → 링버퍼(표시) + 누적 카운터(집계) 분리.

| `src/lib/prefilter.ts` | 사전 매칭, 리스크 1차 탐지, 도배 탐지, CPM·스파이크 |

## 층화 표본 설계

표본이 이 파이프라인의 핵심이다. **단순 무작위나 말단 N건은 대표성이 없다.**

원칙 세 가지:

1. **각 축·클러스터에서 대표를 뽑는다** — 6축 각각에서 최소 1건 이상. 한 축이 표본에서 통째로 빠지면 AI가 그 축을 인식하지 못한다.
2. **놓치면 안 되는 것은 전수로 넣는다** — 리스크 후보(혐오·명예훼손 소지)와 질문 후보는 표본이 아니라 **전량 포함**한다. 확률에 맡길 대상이 아니다.
3. **dedupe 결과를 활용한다** — 클러스터 대표 1건에 `count: n`을 붙여 넘기면, AI는 "이 문구가 n번 반복됐다"를 알면서도 토큰은 1건만 쓴다. 정치 채널은 복붙 구호가 많아 압축 효과가 크다.

표본 크기는 상수로 두고 튜닝 가능하게 한다. 크기를 늘려도 CPM과 무관하게 상수라는 성질이 유지되어야 한다.

## dedupe 기준

완전 일치부터 시작하라. 정규화(공백 축약, 이모지 제거, 반복 문자 축약)를 거친 뒤 완전 일치로 묶는 것만으로도 상당한 압축이 나온다. 유사도 기반(편집 거리 등)은 비용이 크므로, 완전 일치의 실측 압축률을 본 뒤에 필요할 때 추가한다.

**측정 없이 정교한 알고리즘부터 넣지 마라.** 어느 정도 압축되는지는 실제 채팅 데이터로만 알 수 있다.

## 사전 작성

키워드·인물·혐오 표현 사전은 코드에 흩뿌리지 말고 별도 상수 모듈에 모은다. 갱신하는 사람이 코드 리뷰 없이도 전체를 볼 수 있어야 한다.

**혐오·단정표현 사전은 기술 판단이 아니라 규범 판단이다.** 어떤 표현을 리스크로 잡을지는 safety-reviewer와 함께 확정한다. 특정 진영의 표현만 잡히는 비대칭 사전은 제품 신뢰를 무너뜨린다. 한쪽에만 있는 항목을 발견하면 대응 항목을 추가하거나 양쪽 모두 제거한다.

## 테스트

기존 6개 테스트와 같은 스타일을 따른다: 의존성 없이 `tsx`로 직접 실행되는 assert 스크립트, `package.json`의 `test` 체인에 추가.

```ts
// src/lib/dedupe.test.ts
import { clusterDuplicates } from './dedupe.js';

function assert(cond: boolean, msg: string): void {
  if (!cond) { console.error(`✗ ${msg}`); process.exitCode = 1; }
}

// 1) 기능
const out = clusterDuplicates([/* ... */]);
assert(out.length === 3, '중복 3종으로 묶여야 함');

// 2) 성능 — 대량 입력을 숫자로 확인한다 ("빠를 것이다"가 아니라)
const big = Array.from({ length: 50_000 }, (_, i) => makeMsg(i));
const t0 = performance.now();
clusterDuplicates(big);
const ms = performance.now() - t0;
assert(ms < 1000, `5만 건 처리 ${ms.toFixed(0)}ms — 1초 이내여야 함`);

console.log('dedupe tests passed');
```

**성능 테스트를 반드시 포함한다.** 이 계층의 존재 이유가 대량 처리이므로, 대량 입력에서의 시간이 곧 계약이다.

## 시뮬레이터

키 없는 환경에서 앱이 동작하는 유일한 경로다. **타입의 모든 필드를 합리적 값으로 채운다.** 하나라도 빠지면 UI가 `undefined`로 깨진다. 필드가 추가될 때마다 시뮬레이터 갱신은 선택이 아니라 필수다.
