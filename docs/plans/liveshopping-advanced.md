## G-1. 시청자(댓글러) 인텔리전스 — "누가 살 것 같은가"

`author` 단위로 댓글을 누적 집계해 **시청자 프로필**을 만들고, 구매 임박 시청자를 띄운다.

### G-1-1. 핫리드 보드 (Hot Lead Board) ⭐ 최우선
- 동일 `author`의 댓글을 세션 내 누적 → **리드 점수** 산정
  - 퍼널 단계 가중(interest 1 · consideration 3 · purchase_intent 6 · purchased 10), 질문 수, 댓글 빈도, 망설임(감점), 단골(가점)
- 단계가 상승 중인 시청자(interest→consideration→intent)를 **"곧 살 것 같은 분"**으로 상단 고정
- 카드: 닉네임 · 리드점수 · 현재 퍼널 단계 · 관심 상품/옵션 · 미응답 질문 여부 · 망설임 사유
- 호스트 액션: "○○님 사이즈 문의에 아직 답 안 했어요 — 지금 답하면 구매로 이어질 확률 높음"

### G-1-2. 시청자 세그먼트 실시간 집계
- **신규 / 재방문(단골·repurchase) / 핫리드 / 구매자(purchased)** 비율을 실시간 도넛
- 단골 입장 시 "단골 ○○님 또 오셨어요" 인사 유도 카드

### G-1-3. 망설임 추적 (Hesitation Watch)
- hesitation_* 태그를 단 author를 모아 **사유별(가격/필요성/신뢰)** 그룹핑
- 사유별 맞춤 반론 처방 + 해당 시청자에게 직접 답할 멘트

### G-1-4. 트롤·스팸 워치
- abuse_troll·spam_promo 반복 author 격리 리스트 + "무시 권장 / 모더레이터 알림"

**데이터 모델(신규):**
```ts
interface ViewerProfile {
  author: string;
  commentCount: number;
  firstSeen: string; lastSeen: string;
  leadScore: number;              // 0-100
  funnelStage: FunnelTag | 'none';// 최고 도달 단계
  interestedProductIds: string[];
  topTags: ShopTag[];
  hesitationReasons: TrustTag[];  // hesitation_*
  hasUnanswered: boolean;
  isReturning: boolean;           // 단골/재구매
  isPurchaser: boolean;
  flag: 'hot_lead' | 'regular' | 'troll' | 'normal';
}
```
**구현:** 클라이언트에서 `analysis.analyses` + 누적 `messages`를 author로 reduce → 즉시 가능. 또는 AI 응답에 `viewers: ViewerProfile[]` 필드 추가(더 정교한 판단). **권장: 1차 클라이언트 집계(무료·즉시), 2차 AI 보강.**

## G-2. 실시간 전환 엔진 — "지금 얼마나, 어떻게 더 팔까"

매출 신호를 시각화하고 **클로징 타이밍을 초 단위로** 처방.

### G-2-1. 전환 퍼널 시각화 ⭐
- interest → consideration → purchase_intent → **purchased** 단계별 인원/비율 퍼널 차트
- 단계별 이탈률 표시 → "고려는 많은데 결제로 안 넘어감 = 가격/신뢰 장벽"
- 추정 전환율 = purchased / (interest+consideration+intent)

### G-2-2. 판매 모멘텀 게이지 ⭐
- 최근 60초 `purchased` 가속도 → "🔥 지금 구매 폭발 중" / "식는 중" 신호
- `shopTimeline`에 `purchasedDelta` 추가 → 스파크라인

### G-2-3. 클로징 윈도우 카운트다운
- (구매 온도 ↑) + (마감 임박 deadline_question) + (재고 임박 stock) 동시 충족 → **"지금 30초 클로징"** 카드 + 추천 멘트 + 타이머
- 클로징 후 구매 인증 증가량을 측정해 효과 피드백

### G-2-4. 멘트 효과 추적 (Mention Lift) — 준실시간
- 호스트가 혜택 멘트(쿠폰/한정/사은품)를 친 시점을 **수동 마킹**(버튼) → 직후 60초 구매 인증/온도 변화량 측정
- "쿠폰 멘트 후 구매 +4건" 식 인과 근사 → 종료 리포트로 누적
- (STT 연동 시 자동화 — G-5)

### G-2-5. 가격 탄력 경고
- 가격 저항 vs 구매 인증 비율 임계 → "가격 부담 임계 도달, 혜택 재강조" 경고

**데이터 모델:** 대부분 기존 `analyses`/`shopTimeline`에서 파생. 신규 `ConversionFunnel`, `MomentumPoint` 추가. **구현: 즉시 가능.**

## G-3. 방송 종료 후 심화 분석 — "왜 팔렸나 / 왜 놓쳤나"

현재 7섹션 마크다운 리포트 위에 **데이터 시각 분석**을 얹는다.

### G-3-1. 골든 모먼트 ⭐
- 구매 인증·구매 온도가 폭발한 **타임스탬프 TOP3** + 그 직전 상품/멘트(마킹 데이터)
- "20:14에 구매 7건 — 사은품 멘트 직후" → 다음 방송 재현용

### G-3-2. 이탈 분석 (Drop-off)
- cart_abandon_signal 발생 구간 + 직전 트리거(가격저항/품절/신뢰의심) 상관
- "고려→결제 이탈 구간"의 공통 사유 → 개선점

### G-3-3. 시간대별 전환 히트맵
- 방송을 5분 버킷으로 나눠 구매 온도·전환·CPM 히트맵 → "어느 구간이 죽었나"

### G-3-4. 상품·옵션 손익 인사이트
- 상품별 (관심도 대비 전환), 옵션별 수요 랭킹 → **재고 발주/구성 제안**
- "블랙 M은 문의 폭발했는데 품절 → 다음엔 재고 확보"

### G-3-5. 시청자 세그먼트 결산 + 다음 방송 FAQ
- 신규/단골/구매자 비율, 핫리드 중 미전환자 수
- 미응답 질문 → **다음 방송 사전 FAQ 자동 초안**
- 자동 생성 **"다음 방송 액션 체크리스트"**

### G-3-6. 방송 간 비교(트렌드) — ⚠️ 저장 필요
- 회차별 전환율·판매·상품 성과 추이 → E-1(KV)/Supabase 영속 저장 선행 필요

**구현:** G-3-1~5는 세션 데이터로 즉시 가능. G-3-6만 인프라 의존.

## G-4. 진행 보조 고도화 — "호스트가 더 빨리"

### G-4-1. OBS 오버레이 라우트 (기존 로드맵 B-6 재정의)
- `/overlay?token=` 투명 패널: 핫리드 알림·클로징 카운트다운·미응답 수만 압축 표시 → 방송 화면에 직접
### G-4-2. 음성/소리 알림
- 긴급 미응답·클로징 윈도우 발생 시 비프/TTS → 채팅 안 봐도 인지
### G-4-3. 스크립트 어시스트
- 상품 등록 시 **셀링포인트/예상 FAQ 사전 입력** → 질문 자동 매칭 답변(현재 추천답변 템플릿 고도화)
### G-4-4. 멀티상품 타임블록
- 활성 상품 전환을 자동 감지/기록 → 상품별 소개 시간·전환 분절

## G-5. 데이터·신뢰 고도화 — "추정 → 실측"

### G-5-1. 실판매 연동
- 스마트스토어/쇼핑라이브 API로 실제 주문 수신 → `purchased` 추정과 대조, 실매출 표시
### G-5-2. 호스트 발화 STT
- 호스트 음성 → 텍스트 → ① 미응답 질문 자동 해소 ② 멘트-전환 인과 자동화(G-2-4)
### G-5-3. 영속 저장 (E-1/E-7 연계)
- 세션·리포트를 KV/DB 저장 → 방송 간 비교(G-3-6), 시청자 단골 인식 누적
### G-5-4. 한국어 NLP 정교화 (기존 C-10)
- 시뮬레이터/매칭 정확도 ↑ (형태소 분석)

## 우선순위 제안 (ROI 순)

```
1순위 (즉시 가능 · 체감 큰 핵심 3종)
├─ G-1-1 핫리드 보드        ← "누가 살 것 같은가" (사용자 1순위 요청)
├─ G-2-1 전환 퍼널 + G-2-2 모멘텀  ← "지금 얼마나 팔리나"
└─ G-3-1 골든모먼트 + G-3-4 상품 인사이트  ← 종료 후 "왜/무엇"

2순위 (실시간 처방 강화)
├─ G-2-3 클로징 윈도우 카운트다운
├─ G-1-3 망설임 추적 + G-1-2 세그먼트
└─ G-2-4 멘트 효과 마킹(수동)

3순위 (인프라/연동)
├─ G-4-1 OBS 오버레이
├─ G-5-3 영속 저장 → G-3-6 방송 비교
└─ G-5-1 실판매 연동 / G-5-2 STT
```

## 권장 첫 작업: G-1-1 핫리드 보드
- 사용자가 1순위로 언급, 현재 데이터(author+tag)로 **신규 인프라 0** 구현 가능
- 단계: 타입 `ViewerProfile` → 클라이언트 author 집계 유틸 → `HotLeadBoard` 컴포넌트(우측 패널) → (선택) AI `viewers` 필드 보강
- F 트랙과 동일한 풀스택 워크플로우(타입→스키마→시뮬레이터→UI→QA) 적용
